## 优先修复的确定问题

### P0：已落地后的 cancel 重放旧 fall 并永久悬空

证据：[bug-land-cancel-stuck.png](../../test-results/review-pass-3/motion-fix-1/bug-land-cancel-stuck.png)，并有 `boundaries.json` 原始状态。

复现：`play('carried')` → advance .5s → `play('land')` → advance .325s → `cancel()` → advance 5s。

此时 fall.duration≈.241523s，取消前已进入吸震，`root_y=0`、`airborne=False`。`motion.py:211–220` 的非空中、非坐姿分支把 action 清空、elapsed 归零并设置 body_return，却保留旧 fall。`motion.py:453–462` 优先判断 fall，于是重新返回旧 `fall.start`；action 已空，elapsed 不继续走，直到 5 秒后仍悬空。

最低修复：非空中取消必须释放 `fall`；定义每个状态唯一的姿态控制者，不能让过期 fall 压过 body_return。这个修复不需要新素材。回归不仅查 action 为空，还要查几秒后的 root_y、airborne、姿态图，以及连续按两次 cancel。

### P1：fall→land 只交接部分通道，双臂和水平位置跳变

证据：[jump 触地](../../test-results/review-pass-3/motion-fix-1/boundary-fall-jump.png)、[toss 触地](../../test-results/review-pass-3/motion-fix-1/boundary-fall-toss.png)、[carried 触地](../../test-results/review-pass-3/motion-fix-1/boundary-fall-carried.png)。每张取触地前 .04/.01/.001 秒和后 .001/.01/.04/.1/.2 秒。

| 路径 | fall.duration | 触地前→后 .001s 的 armNear | 额外跳变 |
|---|---:|---:|---|
| jump .63s 后取消 | .456435s | -50° → -1.152° | root_y 连续到地面，手臂仍瞬收 |
| toss .735s 后取消 | .524404s | -50° → -.814° | root_x 23.926 → 0，360px 图约 6.73px |
| carried .5s 后取消 | .241523s | -80° → -1.395° | 悬挂姿态直接变站姿臂 |

`motion.py:453–461` 复制 start.transforms，主要只收腿、root_angle、head_pitch/yaw；手臂、root_x、其他上身状态冻结到碰地。过边界改用 land 的新 Pose，所以高度连续不代表身体连续。

最低修复：保留一个明确的 airborne→landing-prep→impact 全姿态链。落下后段把肩肘腕、髋腿、头、尾和横向位移连续交接到触地首帧；需要保留的水平动量继续到接地，归位交给缓冲/支撑步。可以复用 `blend_pose` 的通道集合，但应明确碰撞前后 root 的动力学所有权，避免再次把 root_y 混成漂浮。

### P1：run 腾空高度是布尔阶跃，且侧向前倾符号反了

证据：[boundary-run-flight.png](../../test-results/review-pass-3/motion-fix-1/boundary-run-flight.png)、[directions-run.png](../../test-results/review-pass-3/motion-fix-1/directions-run.png)。

`dynamics.py:85–87` 在双脚无接触时直接 `root_y=-12*env`，有接触又回 0。在稳定周期的 phase=.4/.5/.9/1 有四次开关；2.1Hz 时每秒约 8.4 次阶跃。phase=.3999→.4001 已见高度 0→-12，.4999→.5001 又回 0。320px 渲染约 3px 一跳，不能称为连续腾空。该分支也没产生与根高度一致的 vertical_velocity。

把每个飞行小段归一化为 u，用起止为 0 的弧形轨迹（如 `-H*4*u*(1-u)` 或连续样条），同时给出其导数用于取消。接触瞬间速度可以因冲击改变，但不能把位置作布尔开关。

`dynamics.py:18,91` 的 `direction=-sin(viewAngle)` 已经是 left=-1、right=+1；再写 `-direction*8` 导致 left +8°、right -8°，在当前屏幕旋转约定下两者都后仰。应以 `direction*8` 为起点复核前倾，front/back 仍不该加横向 roll。

### P1：sit/stand 有 IK，但没有完整的坐地承重路径

证据：[lower-sit.png](../../test-results/review-pass-3/motion-fix-1/lower-sit.png)、[lower-stand.png](../../test-results/review-pass-3/motion-fix-1/lower-stand.png)、[睡眠保持后取消](../../test-results/review-pass-3/motion-fix-1/sleep-held-cancel.png)。

`dynamics.py:20` 固定 pelvis=(-20*seat,110*seat)，`104–107` 同时把双足 x 移到 -104/-122、足角转到±33°，contacts 仍保持 True。虽然鞋底参考点可保持高度，但它一直水平滑动。终点骨盆偏高且鞋向下吊，观感仍偏浅蹲/悬坐。`render.py:554–561` 已会按腰到地面高度压缩坐裙；它解决衣服铺开，不能替代骨盆和腿的承重。

建议分三段，先用现有腿链和纯坐裙，不恢复带完整腿尾的旧 sit 整图：

1. **站立→蹲身：** 双足世界位置锁住，髋后下移，膝向正确朝向屈曲；上身小幅前倾以保持支撑。
2. **臀部接地→坐稳：** 明确臀部/裙底接地高度，座面成为新的支撑；再让脚前移或折腿，重新安排膝的前后遮挡，足角接近平放。
3. **起立：** 先把足收至重心下方并确认支撑，随后抬髋伸膝；这不是三条独立通道同步反向缩放。

已制作纯 Pose 覆写诊断：[diagnostic-sit-height-variants.png](../../test-results/review-pass-3/motion-fix-1/diagnostic-sit-height-variants.png)。**它绕过实际 API，只用于艺术定姿建议，不计候选实现通过。** 把 pelvisY 从110改为150/180/190，足角比较-33/0/-10，足前伸比较1/1.3倍。180–190更接近坐地，足角0至-10比下吊鞋合理；但只降腰仍缺臀/大腿承重，尾腹更明显穿地。可从180附近开始联合调髋、膝、足、裙、尾，不建议直接把常数替换后结束。

素材需求：现有腿片可继续作小范围弯曲；若膝/大腿需大角度折叠，应补坐姿大腿/膝面、踝与鞋侧面，并把坐裙分为腿前/腿后遮挡层。保留原 sit 图作为造型参考可以，重新渲染整张旧 sit 会再次引入重复腿尾。

### P1：left/right 的摇头被 head_point 吞掉

证据：[dense-shake.png](../../test-results/review-pass-3/motion-fix-1/dense-shake.png) 与 [head-look.png](../../test-results/review-pass-3/motion-fix-1/head-look.png)。

`dynamics.py:33` 的 shake 只给 head_yaw；`kinematics.py:63–67` 对 left/right 提前返回，只使用 pitch。真实 API 允许在侧面执行 shake，所以不是诊断强制渲染才出现的问题。left/right look 同样丢失 yaw，只剩小俯仰/眼睛变化。

可修选择：补侧面小角度 yaw 的面部/耳/后脑透视和遮挡，或路由到已通过注册的三分之四视图后执行。侧面 pitch 应保留。正面 nod 当前已有实际俯仰，不应把它重新变成只靠转向规避。

### P1：bow 自然结束仍从 7° 突然回 0°

证据：[boundary-bow-end.png](../../test-results/review-pass-3/motion-fix-1/boundary-bow-end.png)。t=1.6999s head_pitch=7°，t=1.7001s=0°。

根因是 `dynamics.py:154` 对所有 eye_closed 都作 `max(head_pitch,7)`，而 bow 整段闭眼。即使 bow 的腰与 head_pitch 曲线已经回零，通用闭眼逻辑又把头抬到最小7°，自然结束不经过取消的 body_return。

最低修复：让低头归睡眠/具体动作的 envelope 控制，闭眼只管眼皮。核对起势同类问题，分别看自然结束与取消，不能只测后者。

### P1/P2：尾部接地、裙腿遮挡与源图关节校准

证据：`lower-jump.png`、`lower-land.png`、`directions-walk.png`、`directions-run.png` 和坐姿高度诊断。

新尾的统一曲线改善了换方向的一致性，但 `render.py:525–539` 将 pelvis 偏移直接加到整条尾曲线；`kinematics.py` 的尾路径没有地面约束。下蹲/吸震时尾腹随骨盆越过足底线，降低坐姿后更明显。应在保持尾根连接的前提下改变尾中段/尾尖曲率或加入接地限制，不能只抬尾尖一个点。

`render.py:541–552` 让长裙下摆逐渐锁回原位置。侧面腿虽由 IK 计算，实际多数被平直长裙遮掉，走跑读感弱。增加节点或通过数值测试不能证明腿动作可见；需要真实服饰前后分片、合理开口和膝/鞋层序。

`render.py:502–523` 的髋、膝、踝、sole 来源是 puppet 的艺术 UV，而不是图像自动识别。该链的存在已确认，但本轮没有把每个 UV 都当成解剖真值。尤其高跟鞋应分清脚踝、鞋掌与后跟地面接触；如果 IK 达不到目标，不能让末段从 actual ankle 拉到固定 sole 来掩盖距离误差。后续需要在真实图上同时标出骨点、皮肤/鞋边界，并看极值姿态有无鞋形拉伸。

## 修复顺序与视觉回归门槛

1. **先修状态所有权：** land 已接地再 cancel、重复 cancel、取消后停留5秒，不能再出现旧 fall；检查 `airborne=False` 与实图落地同时成立。
2. **统一触地交接：** jump/hop/flap/toss/carried 的空中取消，取接触前后1毫秒及相邻1/60秒帧；肩肘、髋、脚、头、尾和水平位置不得突然更换。冲击有速度变化可以，身体位置瞬移不可以。
3. **修 run：** 对四个支撑切换边界各取前后帧；根位置连续，vertical_velocity 与曲线一致；left/right 向前倾，front/back 不横向后仰。然后复看实际裙下的腿和鞋能否表达步态。
4. **联合定坐姿：** 先定落地终点，再定进入/退出路径。足锁地段的世界坐标不漂移，座面接地后才解除足约束；裙、尾和鞋不穿地。sleep 必须保持稳定坐姿，取消先醒再有支撑地起立。
5. **修独立语义漏洞：** profile shake、bow自然结束、flap 翼结构、walk跨步和 dance 节拍。nod 保留新的正面俯仰投影，并继续检查眼/眉/口与发丝同一头表面的相对位置。
6. **再验收方向入口与手型：** 当前 hand 本体的条件通过，不能覆盖 turn/spin 的整身重影或 point 的多掌轮廓。新方向系统和手掌素材需要另一个冻结候选实际图，不能在本报告中提前认定。

每次修复先覆盖对应失败边界，再看完整动作的起势、极值、结束和取消。先以可靠方向达到真实图片可读性，再扩展其他方向；不能以隐藏失败方向、只看正态帧或把 API 路由成功算作动画成功。

## 证据阅读注意

- `land.png` 的标签时间从请求 land 开始，包含先前 carried 产生的落下段；Pose.phase 才是吸震阶段进度，不能直接拿总秒数除 .65 解释。
- `peak-cancel` 的相位是取样候选，不代表所有动作都在完全相同的物理阶段取消；其原始 Pose 存于 JSON。run 的这张极值取消选到支撑期，不能把它外推为所有腾空期取消已通过。
- `diagnostic-sit-height-variants.png` 是唯一有意直接改 Pose 的艺术对比；其余本报告引用的动作/边界图走实际 Animator API。它没有修改候选代码，也不是实际坐姿动作验证。
- 这里查的是冻结候选的动作和真实渲染，不是 19 个表情的新一轮逐项验收，也没有复核主上下文在候选之后宣布的修复。
