# 左右侧面与三个后向视角模型审查

审查基线：`linux/qt-wayland`，提交 `a219dc3`，2026-10-31。范围：`left`、`right`、`back-left`、`back`、`back-right`，以原包 `front-left` 和 `coopanion-gpt-dragon-thumb.png` 为身份基准。仅审查、生成诊断图和本报告，没有修改运行代码、rig 或角色素材。

结论：五个方向能被加载，也确实使用了独立的侧面/后面头身图；但尚不具备连续转身和动作验收条件。主要阻断项是**裁片串格和截断、后侧头发重复且遮挡顺序突变、右侧脚/身体关节未按视角重绑定、后向左右手语义沿用前向、右侧跑步向后倾**。这些不是统一调一个缩放值能解决的问题。

优先级：P1 为当前用户可直接看到、应在下一轮模型交付前修复的问题；P2 为在正确裁图与结构后进行的形态/动作精修。本报告没有把透明 PNG 查看器的低 alpha 杂色当成证据。

## 可随仓库保留的证据

- [五方向静态／举双手／跑步](evidence/side-rear-motions.png)：每行依次为该方向静态、`raise-both @ 0.8s`、`run @ 3.3s`。可见侧面举手被头发遮掉、右侧跑步向后倾，以及后侧服装/发片差异。
- [污染和截断的运行素材](evidence/side-rear-contaminated-parts.png)：第一行右侧两翼与背面远翼，第二行两张后侧尾巴与左后侧长发，第三行两张后侧头图与右后侧裙图。灰底上可见实心相邻格碎片和水平截断。

复现环境：`QT_QPA_PLATFORM=offscreen PYTHONPATH=linux linux/.venv/bin/python ...`，`QGuiApplication` + `DragonRenderer(model_directory())`，输出宽 768；先渲染 ARGB，再用 `QPainter` 合成到 `QImage.Format_RGB32` 的 `#b7b5bf` 灰底。动作使用 0.05s 或 0.025s 连续步进，未把数秒一次传入有 0.1s 上限的 `advance()`。原图连通域测量阈值为 alpha > 128，只用于测量，没有清洗或阈值化素材。

## 动作核实：哪些保持方向，哪些实际先转回前侧

以下是 `Animator.play()` 的真实行为，已用 `routing.json` 对五方向逐一记录。不是“后侧所有动作已经实现”的验收表。

| 动作组 | left / right | back-left / back / back-right | 审查结果 |
| --- | --- | --- | --- |
| 左右歪头 | 保持侧面 | 保持后向 | 已看 ±12°的真实帧；头发重复、颈根与各部件比例问题见上。没有故意改 pose.view 冒充支持。 |
| 抬左/右/双手 | 保持方向 | 保持方向 | 两侧多被头/发遮住；后侧左右手语义错误；固定整臂旋转不能替代视角姿势。 |
| 走路/跑步 | 保持方向 | 保持方向 | 扩展裙图没有可响应裙摆动作的分层；右侧腿轴错误且跑向后倾；后侧近远脚投影未重做。 |
| 拎起/落地/画布内抛落 | 保持方向 | 保持方向 | 拎起袖/手可读性不足；1.5/2.0s时action确实仍为carried、手脚姿态保持，但root_y的-30×env抬升已衰减回0，不是持续悬高。落地只给 upper 增加约22单位纵向平移，整张连体裙一起下移，腿根不随之压缩；应补髋/膝压缩和裙摆形变，检查落地帧不穿地。抛落同样继承这些绑定问题。 |
| 站起 | 保持方向 | 保持方向 | 从默认站姿播放只见轻微动势；坐姿本来会转回front-left，不能据此声称“后面坐着再站起”已经实现。 |
| 招手/张望/点头/摇头 | 保持侧面，已补采样 | 先 turn 到 front-left 再播放 | 后向缺原角度动作，当前是明确回退设计；侧面招手被头图遮挡。 |
| jump / hop / sit / sleep / dizzy / bow / shiver / flap / dance / point / pet / poke | 先 turn 到 front-left 再播放 | 同左 | 不把这些当作五方向通过或失败的本地动作；若产品要各视角原位执行，需补动作和素材。 |
| turn / spin | 经其他已加载视角 | 同左 | 已实际渲染序列；硬切暴露静态比例、脚锚和长发层序突变。 |

此外 `Animator.set_expression()` 对所有非 front/front-left/front-right 直接改到front-left；侧面虽有 runtime眼睛，选择表情仍会回到前侧。`DragonItem.setSpeaking/setListening` 仅在没有 face 的方向回退，故 left/right 能在侧面说话/倾听，后向不能。报告不把“无脸的后向表情”强行判成绘制错误。

## 转向时的脚锚与尺寸：不要用全图外接框对齐

静态测量使用各腿纹理最底6行 alpha>128 像素的平均横坐标，按该腿的 `box` 映射到设计坐标；y为最低高alpha像素。此表用于量化投影差异，不要求左右脚站姿的每个像素完全对称。

| view | 远脚底 x,y | 近脚底 x,y | 双脚中心 x | 相对原左前侧中心偏移（768像素图） |
| --- | --- | --- | --- | --- |
| front-left | 373.49,960.00 | 443.44,966.00 | 408.47 | 0 |
| left | 398.69,961.88 | 446.53,967.83 | 422.61 | +8.49px |
| back-left | 383.93,961.78 | 467.02,967.73 | 425.48 | +10.21px |
| back | 396.07,958.78 | 473.33,958.78 | 434.70 | +15.74px |
| back-right | 383.93,961.78 | 467.02,967.73 | 425.48 | +10.21px |
| right | 520.73,961.74 | 544.82,967.74 | 532.78 | +74.59px |

`back-right → right` 双脚中心跳了约107.3设计单位，即768图64.4px。实际脚投影可随转身变化，但这种量级再配上 right 的异地髋轴，表明共同身体转轴没有建立。头pivot同时从 back-right的x456.10变为right的x507.33，再到left的原x425；`render()`只使用统一外层平移 `(150,220)` 与 root旋转轴 `(425,969)`，没有每方向的注册补偿。

纵向完整轮廓大多从768图y171到712，说明**角顶/全身外接框“差不多高”不能证明比例对齐**。back的最低轮廓y707，比其他方向高约5px；更大的问题是后侧头里压进了长发、右后裙真轮廓被碎片压短、右侧脚的水平重心偏移。尾巴左右摆开也会改变全图宽度，因此不能用包括尾巴的bbox中心注册角色。

建议建立固定的颈根、左右肩、骨盆、脚底中线和角顶/眼线参考；每 view存显式 landmark 与 root校准。先确认脚底共同落地线和骨盆转轴，再设置各部件box；最后让头、发、翼根与尾根落到对应解剖点。若后续加入转向插值，应插值已对齐的骨架/图像，不能用淡入淡出隐藏尺寸跳动。

## 主上下文建议实施顺序与验收

1. **P1裁切**：按原图逐件标定，去掉上述明确串格来源、恢复截断轮廓；检查干净PNG的实际alpha主轮廓。更新 `assemble_dragon.py` 时必须保留每个生成图自己的裁框，禁止重新回到一套 `GENERIC_CROPS` 覆盖全部方向。重裁后同步更新rig与素材校验清单。
2. **P1结构**：统一后脑/长发的拆分，去掉重复发量；让三个后向视角使用连续遮挡关系。核对原服装结构，不通过遮住全身来消除动作接缝。
3. **P1绑定**：逐方向显式标定颈、肩、髋、翼根、尾根，先解决 right 的腿与躯干注册；不用肤色中心代替解剖关节。镜像局部片时同步镜像根UV/关节，旋转符号和近远顺序分别验证。
4. **P1动作**：解剖左右手映射独立于near/far；右向跑步朝前倾；手势需要可见的前臂/手层，走跑/落地需要可动裙摆与下肢压缩。
5. **P2一致性**：最后校准头形、脸/五官比例、衣褶、后发细节；保留右侧看不到左侧结饰等正确非对称性。

验收最低集合：八方向同一中性时刻；逐方向左右歪头极值、左右/双手极值、两帧反相走路和跑步、拎起起始/保持、落地最大压缩；0.05s步进turn/spin。必须先在768灰底看部件连接，再在实际桌宠尺寸看动作是否能辨认。共同要求为：无相邻格实心碎片、无平切发梢/尾巴/裙边、脚底/骨盆转轴连续、转身不换头身比、肩/颈/翼/尾连接不断、解剖左右手正确、角色朝行进方向倾身。没有原视角实现的动作应明确标记回前侧，不以回退帧充当该方向动作通过。
