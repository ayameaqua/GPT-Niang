## 阻断问题与可执行修法

### P1：空中动作重播/替换仍会落入普通姿态淡回

普通 `cancel()`、换 nod/wave 已保留飞行所有者，不等于换 jump/hop/toss/flap 也成立。补充真实 API 复现如下，全部已看图：

| 原动作与时点 → 请求 | C7 行为 | 证据 |
|---|---|---|
| jump t=.63 → jump 或 toss | 原顶点 y=-125，同刻 airborne 变 False；+.07 y=-62.5，+.14 y=0，vy 保持 0，再从地面蓄力起跳 | [重播 jump](../../test-results/review-pass-3/motion-c7-visual/air-replace-jump-jump.png)、[换 toss](../../test-results/review-pass-3/motion-c7-visual/air-replace-jump-toss.png) |
| toss t=.7 → jump | 从 y=-163.64 在 .14 s 内拉回地面，原 vy=-77.92 同刻变 0 | [toss→jump](../../test-results/review-pass-3/motion-c7-visual/air-replace-toss-jump.png) |
| flap t=.7 → jump | 从 y=-40.11 淡回地面，再次蓄力；飞行标志先于实际触地清除 | [flap→jump](../../test-results/review-pass-3/motion-c7-visual/air-replace-flap-jump.png) |
| run t=1.19 → hop | 原 y≈-.377、vy≈791.29，余弧约 .476 ms；被换成 .14 s 姿态淡回，取消已修好的短弧策略在此入口失效 | [run→hop](../../test-results/review-pass-3/motion-c7-visual/air-replace-run-hop.png) |
| carried t=.5 → toss | 从 y=-35 先降地，+.22≈0、+.30 双足站地，再+.40向上跳；不是从当前抓取高度抛出，降落阶段 vy 也未反映位置变化 | [carried→toss](../../test-results/review-pass-3/motion-c7-visual/air-replace-carried-toss.png) |

根因在冻结 `motion.py:180–204`：`('carried','jump','hop','toss','flap')` 整组绕过落地续接，并清除 `fall`；随后进入 `body_return=[previous,0,.14]`。目标预设从地面相位 0 开始，`blend_pose()` 对 root 数值插值，却采用新动作的 airborne 与速度语义。`dynamics.py:166–173` 的 carry 残量还会优先覆盖 toss 的 root，产生“放回地面再跳”。原数值计划只针对 cancel/nod/wave，因此没有覆盖该入口；后补结果见 `motion-c7-visual/air-replace.json`、`air_replace.py`。

最低修法：新抓取 carried 可有独立抓取策略；其他地面起跳预设在角色已腾空时应保留旧 flight owner/elapsed，先走其余弧与 land，再执行 `after_land` 中最后请求。重播同一跳跃也一样，不得先清 fall。若产品希望空中二次冲量，应明确以当前 y/v 为初值，连续接轨迹，不能复用地面蓄力段。真正的 carried→toss 要从抓取高度与释放速度出发，关闭地面蓄力，着地前不允许 ground 状态。

### P1：身体换材质与头部横条仍使转向失败

在真实 front→spin 中，以下不是一个 32 ms 动画帧跨度，而是切点前后 **10 μs**：

| 实际时间 | 切换 | 已看到的跳变 |
|---|---|---|
| .4105462→.4105562 | front→front-left，mix .5 | 衣领、肩、围裙、下身、靴及手臂来源切换 |
| .5500730→.5500830 | front-left→left | 衣侧、手臂和鞋外形换源 |
| .6568842→.6568942 | left→back-left | 长发、翼根、裙内结构跳变 |
| .7532246→.7532346 | back-left→back | 后发、后裙与脚形改变 |
| .8467754→.8467854 | back→back-right | 颈部皮肤突然露出，后发和裙源改变 |
| 1.0499170→1.0499270；1.1894438→1.1894538 | right→front-right；front-right→front | 上身、裙摆、靴同类切换 |

全套证据：[全身阈值 1](../../test-results/review-pass-3/motion-c7-check/spin-camera-thresholds-full-1.png)、[全身阈值 3](../../test-results/review-pass-3/motion-c7-check/spin-camera-thresholds-full-3.png)、[全身阈值 6](../../test-results/review-pass-3/motion-c7-check/spin-camera-thresholds-full-6.png)，同目录全身/头部 `1..6` 均已看。部分恰在 `.5` 的帧受浮点方向影响落在前/后源，报告以明确的前后帧判断。

冻结 `render.py:525–540` 仍按 `view_mix<.5` 选择整个 native view。`_render_body_palette():605` 插值外轮廓，但颜色源仍是 `_body_palette(pose.view,kind)`；内侧衣线、肩、裙结构及腿/臂来源没有同一解剖坐标配准。外轮廓近似连续和零 fold-rejection 不能证明内部纹理连续。应按胸肩/腰胯/衣摆/腿等真实标志进行分层配准或单材质绕体投影，再进行遮挡更替；避免整人透明叠影，也避免仅继续加外轮廓采样点。

头部中间角度出现刘海横断、颈部横条和发侧波纹。左右回眸的 `peak cancel +.14` 特别清楚：[左回眸](../../test-results/review-pass-3/motion-c7-visual/head-return-look-back-back-left.png)、[右回眸](../../test-results/review-pass-3/motion-c7-visual/head-return-look-back-back-right.png)。`head.py` 分行材质/皮肤窗口与源片切换交头部代理定位；本报告确认像素失败，不把头部局部源片故障全部归咎于 body palette。零 head-rejected 也未检出这些裂带。

turn/spin 的尾已在开始统一收起、转身全程遮挡、结束统一展开，所看 51 帧没有旧版每 45° 收展闪烁。这一局部改善不能抵消头/身切换失败。触发自动转向的动作入口也继承此失败。

### P2：坐站中段踝目标进入内不可达半径，鞋骨被压缩

不是“两段总长太短而向外伸过头”。真实 front-left 作者骨长如下，单位均为设计坐标：

| 腿 | 髋→膝 | 膝→踝 | 两段总长 | 内不可达半径 `abs(a-b)` | 作者踝→sole |
|---|---:|---:|---:|---:|---:|
| far | 82.994925 | 108.867287 | 191.862212 | 25.872361 | 91.765509 |
| near | 80.820000 | 122.880763 | 203.700763 | 42.060763 | 85.953299 |

站立原目标距分别 191.644258、203.644907，在有效范围内；所以本次可复现主因是坐站动作路径，UV 长短差使可弯曲的内圈边界更严格，不能直接判原 rig 静态“偏短”。

| 实际 API 样本 | far/near 目标距 | 内圈不足量 | IK 移动踝量（含 .05 margin） | 最终鞋骨/作者鞋骨 | contact |
|---|---|---|---|---|---|
| sit t=.500；stand t=.450 | 11.299108 / 26.318920 | 14.573253 / 15.741843 | 14.623253 / 15.791843 | .876441 / .870572 | False / False |
| stand t=.216（p=.18）取消后 +.350 | 7.372010 / 14.327133 | 18.500351 / 27.733630 | 18.550351 / 27.783630 | .951340 / **.678298** | False / False |

第一组 seat=.68359375，pelvis≈(-19.85177,178.66590)，足 x≈-7.7632/-9.1068；第二组 seat=.726464384，pelvis=(-20,180)，足 x≈-19.9161/-23.3631。骨盆已经降到座位，但足还在胯附近，且腿段不等长，目标离髋过近。

`solve_leg()` 返回被限到可达圈的 `actual ankle`；`render.py:650–657` 却仍用原 `sole` 拼成 `posed=[hip,knee,actual,sole]`，所以 `skin_point()` 必然缩放 boot。已在 [坐下中段](../../test-results/review-pass-3/motion-c7-visual/lower-sit.png) t=.4/.5 与 [站起取消](../../test-results/review-pass-3/motion-c7-visual/reach-stand.png) +.34/.35/.36 看到鞋筒/鞋跟压短。明细为 `motion-c7-visual/reach-metrics.json`。

修复优先顺序：保留刚性 foot 向量，由锁定 sole 反算 ankle；协调 pelvis 和足的伸出/收回路径，使目标避免内圈，必要时给有依据的髋/膝深度，而非压短 boot。`dynamics.py:32–34/116–122` 当前骨盆 `smooth(seat/.72)` 与伸腿 `smooth((seat-.62)/.38)` 的相位差需要调整；可先搜索更早的伸腿窗口及较平缓的降胯，再以两腿最小可达距约束筛掉不成立路径。**本次出错样本 contact=False，不是支撑脚漏锁；修法仍不能在 contact=True 时把 sole 一起 clamp 掉。**

单原裙的单调折叠已优于旧双裙：坐姿终态可读为贴地坐着，裙摆落地，没有两件裙交叉透明，也未见旧坐垫紫条。但此改进并未解决下蹲/站起中间鞋骨问题，sit、stand、sleep 的完整路径仍不通过。
