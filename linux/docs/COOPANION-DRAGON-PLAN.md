# Qt 龙娘分层动画与对话气泡实施计划

计划日期：2026 年 10 月 30 日。实施更新：2026 年 10 月 31 日。状态：P1 可动原型已接入，P2 补图与试验绑定进行中；尚未完成模型 V1。当前能力和待办见 [模型工作区](../models/dragon/README.md)。

本轮保留 GPT-Niang Linux 的 Qt Wayland 窗口、额度查询、设置与 KDE 集成，以 Coopanion 的 GPT 龙娘 **v1.1.0 形象包**为角色基底。模型 V1 保留原包全部表情、动作和交互表现，补全多视角差分、歪头、抬手以及文字对话气泡；模型 V2 增加骑自行车。大龙娘已取消，两个版本都沿用同一只 Q 版角色。

用户已确认继续使用现有 Qt 程序。本轮扩展的是角色与气泡，不迁移 Coopanion 的整套应用、模型供应商、语音识别、电脑操作或 World 框架。下文中的 V1、V2 是角色功能阶段，不改变上游 Windows/macOS 的 1.3.6 版本号。

## 2 必须保留的完整基线

先逐项建立原包演示与目标 Qt 演示的对应记录，再制作扩展。下列能力不得以更少的动作占位，也不能用相同动画换多个名字完成验收。

| 类别 | 必须保留的项目 | 验收方式 |

| 19 种表情 | 平静、开心、眨眼、喜欢、害羞、惊讶、生气、难过、犯困、思考、得意、嘟嘴、担心、认真、慌张、害怕、期待、大哭、疑惑 | 动作预览面板逐一播放；表情含义可区分，可回到平静 |
| 18 种动作 | 站起、跳、小跳、张望、转身、点头、摇头、转圈、坐下、睡觉、晕、走走、跑、招手、鞠躬、发抖、扑腾、跳舞 | 逐项检查起势、保持或循环、结束；坐下和睡觉保留持续状态 |
| 眼神与面部 | 自然眨眼、视线跟随、眉眼联动、原包已有说话口型、倾听和思考表现 | 不把原静态角色的无嘴设定强加给此基底；目光和口型具有独立控制量 |
| 身体附属部件 | 头发、呆毛、龙翼、龙尾、裙摆及饰物跟随身体运动 | 不脱离连接点，不穿帮，不随动作意外缩放 |
| 鼠标互动 | 戳、摸头、拎起、摆动、放下、抛落及落地反应 | 角色交互事件与动作回执对应；桌面运动范围按第 5 节处理 |
| 角色与程序 | 配色、服装、身体比例、角色尺寸设置、菜单、退出、额度气泡及失败提示 | 动画故障不阻塞额度查询；可退出并正常重新启动 |

## 3 模型 V1 新增内容

### 多视角差分

统一设计八个身体朝向：正面、左前侧、右前侧、左侧面、右侧面、左后侧、右后侧、背面。每个视角保留同一角色的头身比、角、发饰、衣服、翅膀、尾巴、颜色和线条处理。左右非对称饰物保持真实位置，不能直接镜像后忽略差异。

正面、左右侧面和背面需要独立补图；斜侧面等中间视图依据相邻视图制作。不能把原正面或斜侧图横向压扁当作侧面，也不能把正面翻转冒充背面。转向时同时改变遮挡关系、绘制顺序、连接点和视线范围。

| 视角 | V1 覆盖 | 转场要求 |
| --- | --- | --- |
| 正面及左右前侧 | 完整 19 表情、18 动作和新增手势 | 作为主要对话视角，可自然回到待机 |
| 左右侧面 | 待机、走跑、歪头、抬手、招手、坐下、转向、倾听和说话 | 眼睛、鼻嘴、远近侧手臂及翅膀遮挡正确 |
| 背面及左右后侧 | 待机、走跑、摆尾、抬手、转向和回头 | 裙装背部、后发、翼根和尾根完整，回到前侧时不跳位 |
| 不适合某朝向的表情或动作 | 先转至能清楚表达的视角，再播放原动作 | 预览面板明确显示转向；不静默丢弃请求或展示背面眼睛 |

这是一张动作适用矩阵，不要求手绘 19 × 18 × 8 套组合。每项基线动作都必须能够调用，且在合适视角完整表现；制作前补齐每个动作的允许朝向和转场目标。

### 歪头与抬手

歪头包括向左、向右、停留和复位；头、角、发饰、眼睛与头发作为一致的层级运动，脖颈和身体保持合理连接。视线可以独立跟随，不用整张角色旋转代替头部动作。

抬手补充左手、右手、双手、指向气泡和从抬手进入挥手。需要分别准备肩、上臂、前臂、手掌及袖口的适用图层和遮挡关系。原包已有的招手仍保留；新增抬手与原招手使用不同的动作语义。

### 新增资源与制作顺序

1. 建立现有 30 个部件的清单，标记可继续使用、需要拆分、需要重绘和缺失的部分。
2. 先制作正面、主要侧面、背面的静态设定，再统一其余视角；检查轮廓、配色、饰物和衣服设计。
3. 拆分可动部件，补画被头发、手臂、裙摆和身体遮挡的区域。角、左右发束、翅膀、尾巴等按运动需要拆分，不机械沿用原来的单片数量。
4. 建立枢轴、父子层级、网格、遮罩、视角切换和动作参数，先完成眨眼、呼吸、视线、歪头和抬手小样。
5. 复现全部基线，再补全新增动作；导出接触表、循环视频和可操作的本地预览。

新画面使用图像生成工具结合参考图逐步制作；文件组装、图层整理、参数和动画由工程工具完成。静态图、自动分层结果及大幅变形都需要检查，不能把生成一张图片等同于完成可动模型。

## 4 Qt 动画架构

现有 Python 继续管理设置、额度与进程；QML 继续承担窗口、菜单和气泡。新增角色资源层、渲染层与动作控制器，不把业务逻辑嵌进某一张图或某个动作中。

```text
鼠标操作 / 本地台词 / 对话结果 / 额度状态
                    ↓
             交互与动作调度
                    ↓
        姿态、朝向、表情、视线、口型
                    ↓
          Qt 分层与网格角色渲染
                    ↓
       动态输入区域 + 气泡及菜单布局
```

| 模块 | 计划职责 |
| --- | --- |
| 角色清单 | 来源与许可、设计画布、视角、部件、绘制顺序、枢轴、命中区及气泡锚点 |
| 渲染器 | 贴图、层级变换、网格变形、遮罩、透明合成和视角过渡 |
| 动作控制器 | 稳定动作 ID、参数曲线、持续姿态、循环、混合、优先级、取消及复位 |
| 交互控制器 | 区分点击、摸头、拖动、放下、动作请求与对话输入，避免重复触发 |
| 气泡控制器 | 额度、台词、对话、提问和状态的排队、替换、关闭与动作联动 |
| 预览与检查 | 逐项动作面板、朝向选择、慢速播放、骨架/锚点调试及录制 |

渲染原型先比较 Qt Quick 的分层变换与自定义网格接入；刚性部件变换不足以复现头发等变形时使用网格后端。需要 C++/QML 组件时，先验证它与项目 PySide6 所用 Qt 的版本和 ABI 一致，再扩展完整渲染。不得直接混用系统 Qt 6.10 与 venv Qt 6.12 的私有接口或插件。

独立动作参数至少包括 `orientation`、`pose`、`expression`、`gaze`、`gesture`、`speech` 和 `motionPhase`。设计画布与运行时逻辑坐标固定，DPR 只用于绘制；切视角、拖动和重复动作不累计改变角色尺寸。

优先级依次为退出/取消、真实用户拖动与输入、用户点选动作、对话/提问、任务状态、自动待机。持续姿态只有在动作规则允许时被打断；取消、失焦、缺失 release 和资源加载失败均有明确复位路径。

原 JavaScript 形象包不直接作为可执行插件导入当前程序。数据与图片经过清单归一化；新代码优先独立实现 Qt 渲染和动作控制。许可证处理见第 10 节。

## 5 Wayland 窗口与输入边界

普通 Qt Wayland 窗口和 KWin 专用规则仍是默认路线：用户拖动调用合成器原生移动，角色位置由 KDE 记忆，尺寸由应用保存。保留原静态渲染路径作为加载失败时的可操作回退。

角色动作与顶层窗口位移分别验收。走跑的步态、空中姿态和落地反应可以在角色画布内表现；**沿屏幕走到指定位置、把整个窗口甩出后运动，以及全桌面光标跟随，不能由普通 xdg-shell 客户端保证。**

| 能力 | 默认 Qt 路线 | 原型阶段必须裁定的扩展 |
| --- | --- | --- |
| 点击、局部视线跟随、动作预览、歪头、抬手、气泡 | 应用窗口内完成 | 动画中的命中区与视觉一致 |
| 拎起、摆动、放下、抛落和落地的角色表现 | 动作系统保留；原生窗口拖动独立处理 | 区分画布内演出与真实窗口轨迹，不把两者写成同一能力 |
| 窗口外的全桌面视线跟随 | 不以不可靠全局鼠标坐标冒充已实现 | 验证窄 KWin 状态通道；只读时仍由规则负责位置 |
| 自动漫游、全局走跑、真实窗口抛掷 | 规则记忆不提供连续定位 | 若列为完整桌面运动的交付要求，使用单独 KWin 运动后端；位置控制权切换后撤掉冲突规则 |

阶段 P0 必须把这些范围写入能力表。需要 KWin 扩展时，Qt 窗口和现有业务继续保留，只扩展经过验证的状态/定位接口；不同时让规则和脚本写回角色位置。相关约束沿用项目既有窗口方案。桌面运动未通过时，不宣称完整复现 Coopanion 的全桌面行为。

动画输入区域必须随视角、手臂、翅膀、尾巴和气泡变化。原静态 PNG mask 不能继续覆盖所有姿态，也不能用包围矩形或所有姿态的大并集挡住透明区域。原型比较变形后区域计算与低分辨率 alpha 检测，测量更新成本和命中延迟；气泡关闭立即移除其输入区域。

角色锚点、脚底基线和气泡锚点保持稳定；开合气泡不移动角色。所有动作最大范围计入画布，避免抬手、跳跃、转背面时被裁切；窗口空白仍可穿透。

## 6 语言与对话气泡

V1 将“语言/对话气泡”细化为中文文字表达、文本输入、回复展示、提问选项、状态提示与说话动作联动。语音识别和真实语音合成属于宿主服务，不因保留原包口型/倾听动作而自动获得；本轮不迁移 Coopanion 的 ASR、麦克风快捷键或电脑操作框架。

| 气泡 | V1 行为 |
| --- | --- |
| 额度 | 保留实际额度窗口、重置时间、成功/尝试时间、刷新及旧数据提示 |
| 台词 | 本地基本语录，支持与表情、歪头、招手等动作同时或顺序播放 |
| 说话 | 逐字显示或立即显示，支持暂停、继续、关闭和完整文本；口型与说话状态联动 |
| 提问 | 按钮选项与自定义文本回答，答案只提交一次，取消与超时有明确状态 |
| 对话输入 | 可键盘输入、发送和取消；使用正常接受焦点的对话窗/输入弹层，角色刷新不抢焦点 |
| 状态 | 读取额度、等待输入、连接失败等有真实来源的状态，不能将额度刷新冒充 Codex 正在执行任务 |

气泡优先级为用户输入/提问、主动查看的额度、当前对话、状态、自动台词。原包动作名字可映射到新的稳定动作 ID；只解析允许的动作标记，不把台词作为脚本执行。长文换行与滚动，中文标点、emoji、连续点击和异步关闭均纳入验收。

文字内容通过 `DialogueProvider` 一类适配接口进入 UI，首版先用本地台词与确定的模拟应答验证完整交互。真实生成式聊天需明确数据源、登录/密钥方式和调用范围，再连接该接口；现有只读额度适配器保持原职责，不在其中加入模型调用。未接入真实对话源时，UI 必须明确标注本地台词或演示，不冒充模型回复。

界面初版使用简体中文，台词语言、界面文案和动作名称分开存储，为后续本地化留入口。对话记录默认仅保留当前进程内的必要上下文，不把完整内容写入常规诊断日志。

## 7 模型 V2 骑自行车

V2 在同一 Q 版龙娘上增加自行车，不替换 V1 的站立、坐下和全部动作。先完成左右侧视骑行，再根据效果补前后斜侧；不把 V1 的多视角全部乘以骑行状态作为首轮要求。

| 项目 | V2 必须完成的内容 |
| --- | --- |
| 自行车资源 | 前后轮、轮辐、车架、车把、车座、曲柄、脚踏及必要遮挡层 |
| 骑行姿态 | 上车、扶把、坐稳、低速踩踏、正常踩踏、停止和下车，结束回到 V1 可用姿态 |
| 动作约束 | 手贴车把、脚贴踏板、髋部落在车座；曲柄、左右脚和轮子按相位协同 |
| 角色附属件 | 长发、裙摆、翅膀和尾巴保持完整，避免穿过车轮或脱离身体 |
| 表情与气泡 | 待机、开心、认真等适用表情可复用，气泡锚点随骑行姿态变化 |
| 交互与窗口 | 点击、拖动、取消、退出仍可用；画布留足自行车空间，尺寸与输入区域正确 |

第一交付为可循环的原地骑行动画及完整上下车转场。若需要桌面骑行轨迹，其速度、轮速和移动距离使用统一单位，并沿用第 5 节经过验证的窗口运动后端；不能只旋转车轮就声称完成骑行。

| P5 整合与验收 | 资源缓存、低功耗、设置迁移、安装、回退、真实 Wayland 与长时间检查 | V1 验收记录、完整来源声明、可复现安装、已知限制 | 2–3 |

V1 初步预算为 **14–24 个工程工作日**；素材反复修改、网格接入和实际桌面运动要求是主要变量。若需要 KWin 动态运动桥接，另预留约 2–4 日并在 P0 更新窗口计划。V2 约 5–9 日另计。以上用于安排阶段，不代表完成日期或已经验证的制作效率。

可按 P1→P2/P3→P4→P5 提供阶段预览。P1 小样是验证制作链路，不替代用户要求的完整 V1。先看到并检查小样的动作和身份，再批量扩展，避免将同一种分层错误带入所有视角。

## 9 验收清单

- [ ] 原包 19 表情、18 动作逐一对应且均可触发；持续姿态、取消和复位正确。

- [ ] 点击、摸头、拖动、放下和抛落反应可区分；窗口内动作与全桌面运动分别记录能力范围。
- [ ] 角色、翅膀、尾巴、抬起的手和气泡可命中；透明边缘与内部空隙能操作背后的应用。
- [ ] 中文长文、emoji、输入法、选项回答、连续输入、关闭和失败提示可用；阅读不被自动台词覆盖。

自动化覆盖清单校验、动作调度、转场、事件合并、输入区域计算和设置迁移；图形 smoke 覆盖资源和 QML 加载。真实桌面点击、拖动、跨屏、视觉连贯和气泡阅读仍需要交互记录与动画预览。
