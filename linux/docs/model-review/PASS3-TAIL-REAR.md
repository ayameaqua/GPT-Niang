## 2. 能直接落实的尾巴骨架、素材和遮挡改造

### 2.1 素材交付应先于最终坐标收敛

建议以同一个有尺度的中性尾形做正侧、两后45°和正后投影。五视图不能各画一条“好看的白龙尾”后再对齐根。统一根直径、弧长、背刺序列、紫尖叶片比例，再按视角画可见面；侧面允许轻微非对称纹理，但结构必须一致。

至少交付：每视角中性尾干、根/裙腰遮挡片、独立紫尖；三个后向另有摆向两侧时的表面/尖端差分。背面尾摆到左右时，背脊的位置与紫尖宽度会改变，用同一J形旋转不能替代。被拎起/下落可由足够细的网格表现下垂；若造型变化超出网格能保持的体积，应另画下垂差分，不要把旧平面尾压缩成新透视。

### 2.2 关节与网格

新增 `pelvis → tailBase → tailMid → tailDistal → tailTip`。根区前10–15%弧长固定或接近固定；中段开始摆动，末端延迟更明显。可用8–12段中心线、每横截面至少3个顶点的带状三角网格；关节权重按**弧长**插值。现有 `_mesh()` 按图片 y 行整体横移，无法对U形中同高但处于不同弧长的两段赋不同相位，不能直接复用为尾网格。

### 2.3 pelvis 与遮挡必须一起改

当前 `render.py:PARENTS` 不包含 tail。`_joint()` 不会给 tail 继承 upper 的姿态，而整个 dress 是 upper 子层。于是裙上表示同一臀部位置的点移动了，尾根留在原处。真实骨盆不应因为胸部前倾而同幅旋转，因此完整方案应将上躯干、骨盆/裙腰、裙摆和腿区分：tail跟 pelvis；上身前倾独立；裙腰/髋和腿根共享 pelvis。

临时把 tail 接到 upper 可减少某些画面裂位，但仍会把尾巴跟着整条硬裙一起转，不能替代骨盆层级。下表给出当前错误的大小，便于修复后验证：

|---|---|---|---|
| left | `(13.81,-9.96)` | 17.02 | 下移22.15，tail根未跟随 |
| right | `(-13.81,-9.96)` | 17.02 | 下移22.15 |
| back-left | `(12.22,-2.82)` | 12.54 | 下移22.12 |
| back | `(0,-2.42)` | 2.42 | 下移22.17 |
| back-right | `(-15.03,-3.07)` | 15.34 | 下移22.15 |

[红绿点证据](../../test-results/review-pass-3/rear/tail-body-registration.png)：红为实际独立tail根，绿为相同静止身体点经upper变换的位置；静止两点重合。此图只标静止/run/land，均无整体root旋转，因此点坐标可直接比较。22设计单位约为768渲染中的13.2px，并非抗锯齿误差。绿色点是检查图像随动一致性的参考，不是主张骨盆必须等同胸部骨骼。

分层建议：远翼在后；远尾片按视角在裙后；身体/裙；近尾主干；根遮挡片/近侧裙片；后发与近臂按明确区域遮挡。具体 z 值可重排，不要只凭一条全局数字排序覆盖所有部位。B、BL、BR至少需要尾根受后发遮挡、尾干能覆盖部分后裙的两种关系。尾摆到极端时，紫尖也不应在翼前突然切换层级。

## 3. 实际尾部动作与转向

### 3.1 所有尾部局部运动仍是同一刚体摆动

冻结 `motion.py:pose()` 的 tail 只有：

```python
tr['tail'] = {'a': sin(t*2.8) * (10 if happy_family else 5), 'y': low*.25}
```

五个tail part均 `mesh:false`，没有尾尖关节、长度约束、延迟或根据动作/速度的姿势。空闲 .55s约+5°、1.675s约−5°；相同时钟的run/walk/carried/toss使用同一尾角。整体root可以使角色连尾一起腾空/摇晃，**这不是尾巴的惯性反馈**。

- [left 多时点](../../test-results/review-pass-3/rear/left-tail-times.png)、[right](../../test-results/review-pass-3/rear/right-tail-times.png)、[BL](../../test-results/review-pass-3/rear/back-left-tail-times.png)、[B](../../test-results/review-pass-3/rear/back-tail-times.png)、[BR](../../test-results/review-pass-3/rear/back-right-tail-times.png)。每张含idle、walk、run、carried、land、toss、左右歪头、回眸，四个时点一行。
- `land` .325s 裙身下沉、尾根不动。`carried` 1.5s/2s角色确实保持拎起姿态，不再沿用早期“超时松掉”的旧结论；但尾巴仍保持同一硬U/J，没有下垂或滞后。
- `toss` 整体root升降/旋转，不改变尾根后的弯曲，尾尖没有落后于上抛/落下方向。
- `run` 局部尾角仍按全局时间与idle同相位摆动；衣摆在同处前后扫过尾干，产生遮住/露出的变化。R尾可见率由静止60%到run样本43%、land75%，不是尾自身完成了有意的收展。

动作验收应分别检查尾根锁定、尾干延迟、紫尖延迟、地面/裙摆遮挡；不能只看尾角数值非零。可从根角0–3°、中段5–8°、末端8–12°的低幅度开始，沿弧长加入约.08–.16s滞后，再调动作方向。该数值是调参起点，需播放检查，不是固定审美标准。

### 3.2 转向中的双尾是真实合成结果

`render.py:render()` 分别渲染两个完整角色再 `_mix`。例如从back调用turn，在 .05s 到back-right的mix=.5时，右侧旧尖和左侧新尖同时以半透明显示。[转向接触表第三行](../../test-results/review-pass-3/rear/turn-tail-overlap.png) 可直接见到两边各一个紫尖。BL→B还有高大紫尖和低矮紫尖叠影。

先统一八向投影中的尾根、尾干和末端所在空间，再采用尾链/网格的坐标补间或画适量中间角度。离散素材切换若仍需少量混合，应在投影相近的位置完成；现有坐标差达到数百单位，缩短淡化时长只是把双尾变成跳尾。

## 4. 相关后向动作问题与应保留的已修复项

本节供动作/头部审查组交叉核对，不把未实现的后向动作假装成已验证。

### 4.1 真实动作路由

[back全动作](../../test-results/review-pass-3/rear/back-all-actions.png)、[BL全动作](../../test-results/review-pass-3/rear/back-left-all-actions.png)、[BR全动作](../../test-results/review-pass-3/rear/back-right-all-actions.png) 每格标明“请求动作 → 实际view/motion”。详细路由在records.json。

- 三后向保留方向：stand、walk、run、tilt-left/right、carried、land、toss；turn/spin本来改变方向。
- wave、raise-left/right/both、point、dance全部先转front。不能据前面已举手的画面宣称“后向举手检查通过”。
- jump/hop/look/nod/shake/dizzy/shiver/flap/pet/poke从三个后向先转front-left。bow转left或right，sit/sleep转front-left。
- look-back从BL/BR保持后侧身体、替换侧面头；从back会先转BL。侧面left/right请求look-back也先转到相应后侧。

缺少原方向动作是功能范围问题，不能通过只拍最终转回前方的姿势掩盖。若产品定义允许主动转面，应对用户明确表现为先转身后执行；若要求每方向都能执行，就需要真正的后向姿势/关节。

### 4.2 方向、脚、头颈和衣发跟随

- **已修：** run的左/右侧及后侧upper倾斜已按方向变号；背面run改为腿sy缩短和很小的角度。不能继续引用第一轮“右侧也向同方向倾”的旧问题。后侧静止新鞋/袖与尾形是不同批素材，旧完整atlas只作为tail来源证据。
- **仍有：** 后侧run仍用直腿贴片在髋部旋转，裙是一个upper子层加按y横移的网格。BL/BR某些步态在裙底露出完整大鞋、另一只脚被吞没，腿膝和裙摆没有相应屈曲。背run的sy变化虽比大幅劈叉合理，脚底没有明确的接触/离地控制。
- **仍有：** land通过upper.y增加22下蹲，腿不缩短/屈膝，裙摆下沉超过原脚底。尾根错位是同一缺少骨盆/腿链问题的外部表现；不能只给tail加22而宣布落地动作完成。
- **仍有：** BL/BR虽把长发从整头中分窗并增加mesh，但 `hairBack → head → upper` 仍使长发整体随歪头刚性旋转。12°歪头时发梢大幅横扫腰和尾根，而网格只沿图片y给小幅横向摆动，不能抵消整体旋转或表达迟滞。应让发根随头、长发多段下垂并与肩/背体积相容。
- **需头部组联合验收：** look-back使用侧面头对准后侧头pivot后整图混合；连接点数值一致不能说明耳、下颌、肩后的发根方向一致。当前BL/BR回眸中间时点能看见两组角/头轮廓，需真实中间头向或局部形变；尾巴保持后侧旧U形也进一步增强身体和头的割裂感。

## 5. 建议修复顺序与验收要求

1. **先重画统一尾形。** 五方向全尾灰底并排审图，不遮根、不先装裙；核对同一背刺线、尾干长度/直径、紫尖比例和相邻视角深度变化。特别修掉BL/BR的背刺根点与R的无解释钩形。
2. **再登记真实根截面和pelvis。** 新源明确画出可藏入衣服的连接段；根锁定到同一骨盆，记录sourceUV与worldPoint；帧间实际根与对应身体点偏移应在1–2设计单位内，或者有明确的骨盆/上身分离模型解释。
3. **做后裙/尾根遮挡和近远尾段。** 去头发、加头发、去裙、加裙四组都检查。完整角色中要能顺着可见尾干合理推回后腰，不能只见无来处的紫尖，也不能把根截口裸露在裙面。
4. **加入尾链和动作反馈。** 先idle正/负极值，再walk/run、持续carried、land峰值、toss顶点/落下；尾根稳定，段间不断裂、不自交，鳞片不被拉成薄条，紫尖有延迟。尾不能穿翼、裙、腿或地面。
5. **最后验收转向和全动作。** 检查L→BL→B→BR→R每个25%、50%、75%中间帧及反向；最多一条可识别尾巴，尖端投影不凭空换边。标清哪些动作原方向完成，哪些先转身；未实现的后向姿势不计通过。

最低证据应包含：同尺度五方向静止；五方向全尾/有裙/有发分层；三后向idle两极与run/land/carry/toss四时点；背侧每对相邻方向的混合中点；默认窗口尺寸与768检查尺寸各一轮。自动点位检查只能保证数据一致，必须再看完整源PNG和实际Qt合成。
