## 2. 应先修的根因

### P0：点头与摇头没有实现相应的空间运动

冻结 `motion.py:344–351` 中，点头正面为整头 `y=7*pulse`、`sy=1-.018*pulse`；三分之四和侧面只多了屏幕平面 ±4° 旋转。脸、眼线、嘴、下颌、刘海、耳角都随同一张图仿射变换，没有俯仰深度差。正面最大平移在 320 像素模型画布上只有 1.75 px，整张 470 单位高头图的最大压缩约 2.1 px。看到的是头部上下浮动，不能以“加了 1.8% 缩放”证明已点头。

摇头是整头 ±10 单位横移与 ±3° 平面旋转；0.8 秒里执行三个周期，更像短促抖动。没有左右偏航时远眼缩窄、鼻/嘴偏移、耳与发束交替遮挡。`look` 的 ±6° 也属于歪头，瞳孔最多横移 4.5 单位；张望缺少真正朝向变化和停留。

证据：[点头接触表](../../test-results/review-pass-3/front/action-nod.png)、[摇头接触表](../../test-results/review-pass-3/front/action-shake.png)、[侧/后相关点头](../../test-results/review-pass-3/front/related-nod.png)、[点头连续视频](../../test-results/review-pass-3/front/continuous-front-nod.mp4)、[摇头连续视频](../../test-results/review-pass-3/front/continuous-front-shake.mp4)。

### P0：取消只回收手势和回眸权重，普通头部姿态直接丢弃

`Animator.cancel()`（`motion.py:183`）保存 `hands/look_back`，不保存当前头部变换、视线、根位移；`play()` 替换动作也只有限地保留这两组状态。取消同一 clock 的证据排除了自然呼吸造成的变化：

| 取消的动作 | 取消前 | 取消同一时刻后 |
|---|---|---|
| tilt-left | head.a=`-12°` | `0°` |
| nod（正面） | head.y=`-7`、sy=`1.018` | y=`0`、sy=`1` |
| shake | head.x=`7.071`、a=`2.121°` | x=`0`、a=`0°` |
| look | head.a=`4.243°` | `0°` |
| point | head.a=`-5°` | `0°`；手臂继续回收，头先跳回 |
| pet | head.a=`-1.531°`，强制 happy | `0°`、neutral |
| poke | root_x=`11.087` | `0` |
| look-back | head.a=`-3°` | `0°`；回眸混合权重虽保留，滚转仍跳变 |

证据：[歪头取消](../../test-results/review-pass-3/front/cancel-tilt-left.png)、[指向取消](../../test-results/review-pass-3/front/cancel-point.png)、[取消前后数值](../../test-results/review-pass-3/front/cancel-deltas.json)。手臂 180 ms 回收确实存在，但不能据此宣称整动作取消平滑。

### P0：回眸是在两套不匹配头图之间溶解

`render.py:517–545` 将后侧身体/后发与侧脸组合，随后 `_mix` 两张完整结果。中间帧能看见双角、双耳、双发际和透明面部；头部没有沿颈轴真正转过去。峰值侧脸与身体的基本组合可辨认，但过渡失败。左右侧头的轮廓、比例和发量又不一致，不能靠统一颈点消除这些差异。

`play('look-back')` 还会先把前向角色转到后侧，结束后保持后侧方向。需明确动作的起止朝向设计；若产品语义是一次回头看用户，不能把强制整身转过去、头部溶解、最后背对用户当作完整回眸。当前峰值只采用 left/right 纯侧脸，目光也不明确落向用户。

证据：[三个前向起点的回眸](../../test-results/review-pass-3/front/action-look-back.png)、[五个相关视角](../../test-results/review-pass-3/front/related-look-back.png)、[右前起点连续回眸](../../test-results/review-pass-3/front/continuous-front-right-look-back.mp4)。

### P1：手势在视角层面被转正面替代；指向坐标与真实气泡脱节

`motion.py:163–164` 对全部 `HAND_GESTURES` 设置 `target='front'`。只有 front rig 有 `articulation`；front-left、front-right 和侧/后向都没有相应分段动作。所谓其他角度的抬手、招手，其实是 0.4 秒内先切换/混合方向，再执行同一正面动作。该路径又会出现混合轮廓。见 [全部八个起点的招手路由](../../test-results/review-pass-3/front/routing-wave-all-views.png)。

正面改进应保留：`arm_chain` 的上臂、前臂和手保持连续连接，并不是过去那种整条袖子的单杆旋转。满幅抬左手的肩/肘/腕/指端约为 `[498,504] → [566.943,494.311] → [588.595,427.672] → [598.964,386.084]`，确实抬到了耳眼高度。`raise-left/right` 在正面对应角色自身左右，未发现左右手反了。

但 `pointTarget=[760,280]` 是 rig 常量，与 UI 气泡没有数据连接。冻结 `Main.qml` 中角色 y=350，气泡为 x 居中、y=8、348×330。按真实食指射线和上身变换计算：

| scale | 气泡 x 区间 | 食指射线到 y=338 的 x | 是否碰到气泡 |
|---|---:|---:|---|
| 0.6（允许的最小尺寸） | `[8,356]` | `311.372` | 碰巧相交 |
| 1（默认） | `[8,356]` | `389.441` | **失败：从右侧错过约 33.4 px** |
| 1.5 | `[78,426]` | `557.027` | 失败 |
| 2 | `[158,506]` | `734.613` | 失败 |

默认指尖约为窗口 `[221.030,502.721]`。证据：[默认气泡边界与食指射线](../../test-results/review-pass-3/front/point-bubble-scale-1.png)、[完整计算数据](../../test-results/review-pass-3/front/point-target-metrics.json)。该图使用真实模型渲染和冻结 QML 的坐标构造边界示意，并非声称抓取了实际桌面窗口。不能再以“指向某个 rig 常量”替代“指向真实气泡”。

### P1：右侧嘴在脸外；侧面 wink 关闭隐藏眼

- 右侧 `face.box=[446.5108,302.2843,130.9809,142.3706]` 复用原嘴，算出的嘴中心为 **`[518.550,414.757]`**。考虑头图 `warpY=[.73,.83]` 做逆映射后，该点底图 alpha 约 **5/255**；左侧对应点 alpha=254。右侧嘴确实落在下颌外缘之外，并非查看器低 alpha 噪点。surprised、cry 和 speech 把它变成更明显的悬挂圆点。
- `render.py:250` 在 `oneEye` 时跳过 index=0；但 `:255` 的 wink 恰好只关闭 index=0。因此左右纯侧面仍睁着可见眼，只改变嘴，**没有执行眨眼语义**。
- 右侧可先独立设置 `face.features.mouth={"source":"mouth","box":[98,90,11,9]}`，将嘴中心移到约 **`[518.550,391.978]`**。内存试摆 neutral/surprised/cry+speech=1/happy+speech=1 均回到脸内，见 [候选前后图](../../test-results/review-pass-3/front/candidate-right-mouth.png)。未改正式数据。
- **不要直接给侧面加现有 maskSkin。** `_skin_mask()` 将未做 `warpY` 的头图直接放进 box，和实际侧头投影不一致。先让皮肤 mask 与头图使用同一 warp/投影，再决定遮罩范围；否则会引入新的五官裁断。

证据：[嘴与侧面眨眼对照](../../test-results/review-pass-3/front/mouth-profile-detail.png)、[嘴坐标记录](../../test-results/review-pass-3/front/mouth-records.json)、[右侧嘴局部坐标网格](../../test-results/review-pass-3/front/right-mouth-grid.png)。

## 3. 13 项动作逐项判定

“核心通过”仅表示当前最可读方向中的主要动作可辨认、对应连接在样本中成立；“整体失败”包含其余指定视角、组合、取消等要求。不得把核心通过写成整个动作已通过。

| 动作 | 核心动作判定 | 视角/持续/结束/取消 | 最低合理设计与可实施修复 |
|---|---|---|---|
| look / 张望 | **失败**：眼睛轻移+头部歪转，缺少朝向变化 | 2.7s 可结束；视线 y 起止突变虽小，取消头姿态硬跳；背向会先转前侧 | 眼睛先移，头部偏航跟随；左右各有短停留，再回中。沿固定颈点做 yaw，不用 roll 冒充转头 |
| nod / 点头 | **失败**：正面上下浮动；前侧只附小幅 roll | .8s 两周期偏急；首尾能归零不构成自然点头；取消硬跳 | 颈点固定、真正 pitch；眼线/下颌与头壳深度不同。先做一次约 .9–1.2s 的低头—停留—回中，再加重复点头 |
| shake / 摇头 | **失败**：横移抖动，未出现左右转头透视 | .8s 三周期；取消立即归零 | 小幅 yaw 左—右—中约1–1.4s，眼/鼻/耳与发束有正确透视和遮挡；头心不左右漂移10单位 |
| tilt-left | **核心通过**：三个前向能看出约-12°歪头，五官跟随；整体失败 | 正常18%进入、78%后回收成立；取消瞬回。侧面同一屏幕旋转不能自动证明世界左右倾斜正确 | 明确方向约定；保留颈点滚转，补颈段形变与后发滞后；将取消纳入同一姿态过渡 |
| tilt-right | **核心通过**：三个前向约+12°歪头可辨；整体失败 | 同左；长后发随整个头刚性摆动，缺少惯性 | 同左，正负端点均须查领口与肩发遮挡 |
| wave | **正面核心通过**：抬臂后腕部摆动，肩肘腕连贯；整体失败 | 所有其他起点被转 front；1.7s 内腕部6周期约3.53Hz偏碎；手臂取消有180ms回收 | 保留分段臂；每个方向配实际近远臂及深度，建议抬臂后2–3次更清楚的腕摆，袖摆有少量延迟 |
| raise-left | **正面核心通过**：角色左手抬起，未串手；整体失败 | 2s动作进入/保持/回收可读，手臂取消连续；非正面仍强制转 front | 给 FL/FR/侧面同解剖侧分段臂与肩UV；若产品要求举过头顶，应增加肩/肘目标，当前只是耳侧高度 |
| raise-right | **正面核心通过**：角色右手抬起；整体失败 | 同上；其他角度未实现 | 同上；不可照搬 armNear/armFar 名字推断解剖侧 |
| raise-both | **正面核心通过**：双臂对称抬至耳侧；整体失败 | 双臂连接成立，但跨视角缺失；两侧动作机械同步 | 保留骨链，稍错开起抬/停顿可改善自然感；若为欢呼举手需更高目标和胸肩响应 |
| point | **失败**：食指姿态存在，但默认尺寸射线错过气泡 | 起收有动作；取消头先跳回、手随后回收；其他起点转正面 | 从真实气泡边界反算模型目标；肩肘确定舒适范围，腕/食指瞄准；视线同指向目标，统一头手取消 |
| pet / 被摸头反馈 | **失败**：立即换 happy，随后约±4°小歪头；缺少触碰反应 | 1.6s结束后表情硬切回选定表情；取消头硬跳 | 轻微颈部压缩/迎手、闭眼渐变、发梢或耳朵延迟，最后恢复；这里不要求角色用自己的手摸头 |
| poke / 被戳反馈 | **失败**：换 surprised，整角色水平滑12单位 | .65s无局部受力点、无支撑；取消根位置瞬回 | 输入触碰部位/方向，胸头短促后撤与重心响应，脚保持支撑；允许一次衰减回弹，表情有进入/退出 |
| look-back | **失败**：整身先转后侧，再将两套头溶解 | 峰值轮廓可辨但过渡双头；取消滚转跳变，脸仍溶解回去；结束朝向被改变 | 后侧身体保持，头在同颈根从后侧转到能看向用户的角度；需要中间头图/共同网格及正确后发遮挡 |

| pout | **失败** | 只是小圆口+横向视线，缺少鼓腮或撅唇；需要专用撅嘴轮廓/脸颊形变，不能复用说话O口 |
| worried | **失败：辨识不足** | 眉部线索多被头发遮住，主体接近neutral加小皱口；说话后进一步失去差别。需要可见内眉抬高/下眼睑张力 |
| determined | **失败：辨识不足** | 轻压眼+短横口太弱；说话时短横口也丢失。需要明确聚焦瞳孔、可见眉/上眼睑压角 |
| flustered | **通过** | `><`式闭眼与红晕明显；线条风格较简化，后续可换原画风眼形，但不是本轮最高优先级 |
| scared | **失败** | 眼睛基本仍为neutral，小O口和极小水平抖动不能清楚表达害怕；应有瞳孔缩小、上睑抬起、眉/嘴紧张及短促退缩 |
| excited | **通过** | 星光瞳孔与笑口可辨；说话后仍留有星光，组合身份较稳定 |
| cry | **通过**（前向） | 闭眼泪条+开口可辨；right大开口在脸外失败。可继续改善泪条起点和沿脸面贴合 |
| confused | **失败：动作组合丢失线索** | 主要为2.5°歪头和小眉变化；nod/look会覆盖 head.a，front/FR又没有基底“?”符号，使组合趋近neutral。应以独立表情眉眼线索为主，歪头作为附加层 |

组合证据为 `combo-<起始视角>-nod.png` 和 `combo-<起始视角>-wave.png`。19表情每行三帧，全部开启 speech。较易阅读的分页例：[正面点头第1页](../../test-results/review-pass-3/front/combo-front-nod-page-1.png)、[正面点头第3页](../../test-results/review-pass-3/front/combo-front-nod-page-3.png)、[FR起点招手第4页](../../test-results/review-pass-3/front/combo-front-right-wave-page-4.png)。FR起点招手页实际已是front，这本身就是视角被替代的证据。

**说话整体失败，不能以“O口在变化”验收自然说话。** `speech=.35+.65*abs(sin(12t))` 始终不低于.35；只改变一个椭圆的长宽，没有闭口间隙或口型转换，也不读取音节/音量。启停时马上切换嘴；happy/smug/pout/worried/determined 的口形差别被统一覆盖。最低可以先做闭口、窄口、圆口、宽口的时序/能量状态，嘴角保留表情偏置，启停约100–160ms过渡；有真实音频时由音量或viseme驱动。全部口型须在每个头部投影后的脸内。

## 5. 最低可信的头部投影与补图要求

主上下文提出“固定颈点的2.5D曲面投影”方向合理，前提是实际产生空间线索，而不是改名后的缩放。

1. **建立共同头部坐标与地标。** 每个头至少标颈根、下巴、双眼内外角、眉、鼻/嘴、前额发际、耳根、角根。front现颈点 `[425,460]`，FR为 `[443.391,450.949]`；原FL从原rig取得。作为当前静态参考，不因投影再任意移动整组身体。
2. **分层深度。** 头壳/下颌、脸面五官、前刘海、耳角、后发不能都是同一个平面；五官和skin mask绑定同一脸面网格。对以颈点为原点的顶点，俯仰可采用 `y'=y*cosθ-z*sinθ`，偏航采用 `x'=x*cosψ+z*sinψ`，再投影；颈点投影恒定。符号需与屏幕坐标一致。深度值是原画校准参数，应靠地标和轮廓验收，不能把随意深度值当成已正确的3D结构。
3. **先限制角度。** 正面俯仰先做约±10–12°，让眼线/下巴有相对位移、头顶露出量变化、脸宽和耳角遮挡合理。侧面可以围绕颈根真实前俯，仍需处理下颌碰领和后发惯性。不能继续靠平移±7和sy±.018充当结果。
4. **何时必须补图。** 现有2D素材没有抬头下颌底面、低头新增头顶，也没有被刘海遮住的完整额头。若小角度投影已经露洞或拉长发片，应补各前向的低头/中性/抬头参考或隐藏底色，不能无限拉伸现有像素。扩大角度尤其需要补图。
5. **摇头与回眸需要兼容的方向头。** 当前各角度头型/发量/饰物拓扑不一致，单纯颈点对齐再crossfade必然双影。最低需要0/±15/±30°头部中间图或共同三角网格对应点；保持同一角色的发际、角位置、脸比例。将同一网格变形到目标角度后只做小范围纹理过渡，不能整张不同轮廓头图透明叠加。回眸转到更大角度时另需后侧—侧—前侧的过渡头图。
6. **长发与头不能完全锁死。** 根部随头，发梢采用约80–120ms滞后和小幅衰减；颈肩附近发束在正确前后层。当前后发虽然有持续sine mesh，幅度不随头部速度产生响应，不能作为动作惯性的证据。

验收一个俯仰方案时，固定身体与颈点，逐帧看眼线—下巴相对位置、鼻/嘴位置、头顶露出量、下颌—领口距离和发层遮挡。只有头框高变了、整张脸上下走了，应直接判失败。

## 6. 手势骨架、素材与生命周期的可实施顺序

1. **保留 front 的三段臂，补其他方向。** 给 FL/FR 至少各画上臂、袖前臂、放松手、张掌手、食指手；必要时再补侧/背。每段标 `rootUV/endUV`，保证肘腕有少量可遮盖重叠，不露透明端口。原FL整袖图不能仅靠切两刀就保证弯肘可见的新轮廓。
2. **显式解剖侧映射。** front/FL/FR不能只凭Near/Far名字推断左右；例如FR现 `armFar` 是画面左、实际近臂，`armNear` 是画面右、实际远臂。动作状态保存角色左/右，视角rig负责映射节点、旋转符号和投影长度。
3. **按姿态决定遮挡。** 冻结 `_render_view` 将所有分段 forearm 固定 z=19、hand=19.1。它适合当前正面向前抬手的一部分情况，不能直接复制到侧/后向。肩、上臂、前臂、掌应有可切换的近远层或深度；避免远臂穿到整张脸、刘海前面。
4. **指向真实UI。** Main.qml将气泡中心或适当边缘锚点通过角色item逆变换传给模型：先减角色item位置，再乘1280/itemSize，再去掉renderer平移/root变换。`pointTarget`应为运行状态，随scale、窗口和气泡大小更新。手腕瞄准后用食指射线与气泡矩形相交验收，不看角度参数是否变化。
5. **保留表情与动作两个层。** 让眉眼/嘴角的表情参数保留，点头/张望叠加在头部姿态层，语音口型叠加在表情口形上；pet/poke退出时过渡回用户选定表情，不能瞬切。
6. **统一进入、自然结束、取消和动作替换。** 捕获当前完整可见pose及必要速度，包括head pitch/yaw/roll、gaze、root、hands、面部混合；采用约180–300ms可调过渡回到目标姿态。不能只回收hands/look_back。取消同一时刻的下一帧不应发生位置/角度跳变；之后也应避免速度突然折向。
7. **禁止用强制换视角掩盖缺失。** 当前不能实现的视角应明确标注能力，或在产品设计中显式定义“转向用户再招手”；用户要求每个角度都能正确行动时，最终必须交付对应rig动作。

## 7. 下一轮必须按视觉通过的验收清单

- **点头/摇头/张望**：不显示动作名也能分别识别；颈点固定，头部有正确pitch/yaw及脸部透视；320像素和放大图均看得出，不能只看到呼吸式位移。
- **连接**：头颈、肩肘腕全时序不出现灰底裂缝、二重轮廓或未遮住的裁片端口；手腕/指尖尺寸不在过渡中突然变大。
- **视角**：FL/FR手势在相应身体视角执行，解剖左右一致；背侧回眸身体保持，转头过程不出现两套半透明耳角。
- **取消/替换**：在进入、保持、返回三个阶段各取消/切换；取消瞬间位置与姿态连续，随后自然回收。不能只检查动作结束后的同一张站姿。
- **指向**：默认与至少两种非默认缩放下，实际绘制食指射线与真实气泡边界相交，视线也落向同一目标；气泡隐藏时动作语义要明确。
- **表情与说话**：19表情逐项能解释其视觉线索；侧面可见眼确实眨、嘴及最大开口在脸内；说话有闭口与口型变化，仍能看出happy/smug等差异；叠加点头、招手不会丢失表情主要线索。
- **证据**：使用修复后新冻结树重新出30fps连续证据及进入/峰值/退出/取消接触表。必须重新人工看关键帧和连接，不以骨长常量、参数范围、像素有差异、hash更新或测试通过替代视觉结论。

本报告所有“失败”指向上述固定基线。主上下文后来完成的修改，必须用新的快照单独复核，不能沿用本轮的局部通过结论。
