# 动作、表情与朝向调度复核

审查基准：`linux/qt-wayland`，提交 `a219dc3`，2026-10-31。本报告只记录审查；未修改运行代码、绑定或角色素材。使用已导入的 Coopanion v1.1.0 原包以及仓库七个扩展 rig。结论是：**19 个表情、原包 18 个动作及新增 11 个动作均有入口；这证明清单与部分状态机已实现，不证明完整视觉合格。**

## 1. 方法、证据与边界

- 已阅读 `model/{motion,render,item}.py`、全部七个 `rig.json`、原包 `model.json`、基线 JSON、实施计划及 `tests/test_model.py`，并检查实际合成和分层隔离画面。
- 使用 `QGuiApplication`、`DragonRenderer(model_directory())`、`Animator`，以 `1/60 s` 循环推进；没有把大 `dt` 当作完整推进。图像先在 RGB32 灰底上用 QPainter 合成，排除透明查看器对低 alpha 边缘的误读。
- 已实际采样：29 动作 × 8 初始朝向；每组包含发起时、实际动作的 `p=.12/.30/.50/.78/.98`、结束后约 1.5 秒、取消后。需转向的请求先走完 pending turn，再采样目标动作。每个动作都有完整接触表。已逐项检查 29 动作的原基底多阶段表、全方向中段表，另对关节/转场/手势/走跑等高风险项目查看各方向多阶段与放大图。
- 已实际采样：全部 19 表情在 `front-left/front/front-right` 的可达静态结果；另强制绘制左右侧面的 19 表情作为渲染诊断。后者**不是**公开 API 可原地选择侧面表情的证明：公开 `set_expression()` 会返回左前侧。
- 补充实际采样：五个有脸视角的自然眨眼 7 阶段、说话口型 3 个幅度；29 动作中途取消；拎起 0–8 秒；坐下/站起阈值；转身/转圈的相邻中间视图；neutral/angry/scared 与六个动作的组合。
- 未穷举 `8×29×19` 全组合；未做全部像素级关节追踪、真实 Wayland 连续录像、用户拖拽的完整输入链或所有尺寸/DPR。表中“已采样”不等于这些未做项目通过。原包 JavaScript 未在本轮执行，因此不宣称逐帧复刻了上游运行时。

`stand *`：普通站立状态下无独立站起演出；只把 seat 插值回零。侧面坐姿尚未实现，不能因为 stand 不回前侧就声称侧面 sit→stand 已支持。

路由相关的重要事实：

1. 所有 19 表情：F/FL/FR 原地；其余五方向直接 `set_view("front-left")`，**没有 turn 动画**。这是 `motion.py:71–76` 的代码确认，并实际调用全部8×19次 `set_view`→`set_expression`，记录view/action/pending；结果一致。
2. `item.py` 的 speaking/listening 会保留有 `face` 的五视角；后三个无脸视角直接切 FL。已用实际DragonItem逐方向调用setView→setSpeaking/setListening确认；其余侧面表情菜单仍会回 FL，不能把“侧面有脸”误认成所有表情 API 原地支持。
3. 动作自动转前侧后不恢复原朝向；cancel 也不恢复原朝向。`turn` 到相反方向，`spin` 才回到开始方向。
4. `look-back` 在基线的 V1 新动作需求内，但 `MOTIONS` 没有该项，也没有头身分离回头实现。当前 turn 是整个人换图，不是回头。

## 5. 根因和修复顺序

### P1-A：将动作通道与表情通道分开，先修确定的覆盖错误

位置：`motion.py:215–230`。手势先写armNear/armFar，随后 angry/scared 分支无条件写 `-10/+12`。同一表情下左右抬手、双手、招手可视化退成同一个臂姿。这不是素材问题。

主上下文可执行：把身体惊吓/生气反应改成有优先级的加成或只在无显式手势时使用；不要让基础表情覆盖用户动作。为六个已采样动作与angry/scared建立行为回归，比较动作的肩/肘/手目标仍被保留；随后重新查看灰底图。

### P1-B：为“人物左/右”建立跨视角映射，再拆分臂链

位置：`motion.py:215–223`、`render.py:PARENTS/_joint`、各rig `arm-near/arm-far`。当前每只手只有一个arm节点，没有上臂、前臂、手掌/腕、肘。near/far被当成left/right；在背面，画面右边的armNear仍被raise-left驱动，解剖左右相反。手臂z固定，抬高时继续在head/发层后，手掌大量消失。左前侧raise-right、point尤为明显。

主上下文可执行：增加明确的 `anatomicalLeft/anatomicalRight` 到每视角部件映射；用标记点验证再调角。先修三个前向与back的抬左/右/双手/招手关键帧；补独立肘/腕/手形及可见面；按动作阶段决定手掌与头/发遮挡。point需要接收气泡锚点或明确限定的目标区，并有可辨的指尖。不要只把110°改成别的角度就宣称完成。

### P1-C：正面/右前侧需要独立五官布局，不应整块缩放原侧脸

位置：`render.py:129–242,337–351`；front `face.box=[312,315,230,150]`；front-right `[455,315,160,150],flip=true`；侧面 `oneEye=true`。

源 atlas：远眼53×51、近眼65×55，中心约328.5与435.5；嘴中心约373.5。这是左前侧透视布局。正面只是x加42，得到眼中心370.5/477.5、嘴中心415.5；嘴比眼间中点424偏左8.5设计像素，双眼仍不等大。正面的最终中心应以实际脸廓标定，不能把肩部平均值导出的head枢轴当作面部中线。右前侧压缩到160宽后整块翻转，嘴/泪贴下巴。`oneEye`只屏蔽远眼，不屏蔽第二组腮红/泪。

主上下文可执行：为五个有脸视角建立独立眼、眉、嘴、腮红、泪的局部锚点与脸部遮罩；front使用正面几何，FR用其实际脸廓；复用绘画风格而非整块侧脸布局。状态符号逻辑应共用于source与扩展（当前只在 `_render_source` 画），不要靠缺失符号造成thinking/confused/worried几乎相同。分离“闭眼”与“睡觉”：bow关闭眼睛不应自动出现z。

### P1-D：坐/站的持久状态与坐姿过渡分别验收

位置：`render.py:304–307`、`motion.py:125–126,165–175`。`seat<.5`与`>=.5`直接决定整块sit是否显示，以及腿、裙、尾、翅膀是否同时隐藏。实际seat=.463→.500的相邻帧轮廓突然改变。

主上下文可执行：保留持久状态逻辑，加入起坐过渡关键姿态或有遮挡设计的形变/混合；不要仅把阈值挪到另一帧。对坐下、站起和中途取消分别安排连续轨迹；明确侧面坐姿未完成的UI/能力标记。睡觉可以保留坐着睡的设计，但应补头/身放松过程并明确语义。

### P1-E：按方向修正步态、鞠躬和支撑点

位置：`motion.py:188–203,224–227`；七个扩展rig仅覆盖部分head/arm/wing枢轴，**都没有覆盖legFar/legNear**。例如right腿贴图在x465/480，仍使用原基底髋点397/461；left腿贴图位置也改变。`run`与`bow`始终负upper角，不随朝向变号或使用俯仰差分。

主上下文可执行：为每视角标定髋、膝、踝、脚底及wing/tail根点；先做两侧走跑与三前向鞠躬，确保“前倾”与面向一致。正面动作需要俯仰/上下压缩的合适绘法，不是roll侧倾。裙摆与腰、腿各自绑定，增加支撑脚约束，不能让整片衣裙跟upper绕腰旋转就作为步态完成。

### P2-A：拎起、落地和动作交接

位置：`motion.py:138,152,237–244`。carried被排除出动作结束，但使用普通会衰减到零的env；1.5秒后root_y仅剩待机呼吸。land先改变pose.hair，原基底却读取早已写入transforms的warp，导致原基底没有该发丝落地反冲。carried的arm/leg/root_angle起始也没有env，立即跳姿态。

主上下文可执行：分开carried的进入、持续与释放包络；持续悬挂/摆动围绕明确抓持点；land继承上一帧的姿态速度或至少位置，统一发丝参数计算顺序。加入carried→land、carried→toss、raise→wave的平滑交接。当前没有自动toss→land和独立swing动作：swing只表现为carried中的根部正弦摇摆。

### P2-B：八方向换图需先统一轮廓、脚点，再设计过渡

位置：`motion.py:127–142`、各rig `box/pivots`、`render.py:278–282`。turn取四舍五入的离散step；spin取int(p*8)。没有视角间形变、插值或过渡层。方向素材的脚显露、裙长、发量、躯干中心变化会以整张换图方式出现。

640×640、neutral、t=0、alpha>64的整人bbox下边：F594、FL593、L594、BL594、B589、BR594、R594、FR594；top为142–143。**这说明外接框总体高度已大致对齐，不能宣称有巨大的整体缩放错误；也不能把bbox底边当成脚底对齐证明**，背面主要是裙摆，其他方向可能是鞋或尾巴。实际转场仍存在身体重心、脚位置与服装显露跳变。

主上下文可执行：先用解剖/服装锚点统一八视角，再做前向/侧向之间的遮挡转换。相邻视图透明交叉淡化会产生双眼/双手/双尾，不能未经验证就当作解决方案。表达请求回前侧也走明确turn队列，不应在 `set_expression`/speaking里直接切图。

### P2-C：扩展视角附属件运动没有完整继承

代码确认并有分层图：七个扩展rig都没有独立ahoge节点；除front有hair-front外，多数head把前发、角、耳作为整图，原基底的ahoge摇动参数没有对应可动层。dress绑定upper，原基底的skirtFar/skirtNear/apron参数在扩展中无对应部件。故不能凭Pose内存在这些键宣称扩展也有呆毛/裙摆动作。

头颈在小角度下总体保持相邻；正面源neck矩形露得明显，侧面头后发靠绘制重叠遮缝，极值需要补肩颈覆盖。翼/尾在已查看帧没有出现大片完全脱离身体的故障，但固定根点、翻转贴图和不同z仍须按视角核对；裙与长发常掩盖根点，**被遮住不是连接已验收**。隔离图中FR/BL等头发层存在离散残留小片，它们随head而非身体移动，可形成运动中的漂浮碎片；不要把灰底下可见的实色残片和透明查看器伪噪声混为一类。

## 6. 回归与视觉验收标准

本轮已有测试：`QT_QPA_PLATFORM=offscreen PYTHONPATH=linux linux/.venv/bin/python -m unittest linux.tests.test_model -q`，14项通过。它们主要确认状态、数据安全、枚举与合成不同；不少使用纯色synthetic模型。八视角hash不同、手臂角度不同、命中区变化都不能证明画得正确。

补充诊断的29项中途cancel均清空action/pending/seat/sleeping并恢复neutral，2秒后没有复活请求。另在29动作×8初始方向×13相位（3016张320px合成）上检查alpha mask边界：没有碰画布边，最小余量18px，出现在right/run/p=.12。这里只验证这组中性表情离散样本的有效alpha区域；不是全部组合、所有时间或低alpha碎片均已清理的证明。

建议主上下文按上述P1顺序修复后使用以下门槛：

1. **状态回归**：29项可调用、无丢请求；每个不适用方向显示明确转场；sit/sleep持续10秒并能stand/cancel；carried保持8秒仍保持悬挂高度，放下不残留；表情不吞手势；只对确实需要的状态断言新增测试。
2. **左/右回归**：八方向标注人物左肩/右肩、肘、腕与手；raise-left始终移动同一解剖肢体，raise-right相反；背面必须对应正确屏幕侧。手掌在高举平台可识别，举双手不得退化成只有一侧袖口或双手全消失。
3. **脸部回归**：19项三前向逐项比较，另测侧面说话/眨眼；front眼中线、嘴中心与其面部设计一致；FR最大口型及cry不出脸；oneEye仅显示可见侧腮红/泪。angry/determined、thinking/neutral、shy/pout/scared有可解释的独立面部差异。
4. **连接和脚点**：每动作至少起始、两个关键极值、平台、回落、结束/中途取消；额外逐帧检查抬手、跑步、起坐、转向。肩/肘/腰/翼根/尾根不能露灰缝或重复肢体；没有设计意图的支撑脚位移建议控制在1280画布3px内，变更阈值需有视觉理由。
5. **换向回归**：turn/spin及所有自动回FL路径，用逐帧接触表和实时播放一起检查；脚点/头部中心不跳，服装/饰物不换身份，没有双重轮廓；不能只验证最后一帧等于目标view。
6. **画布与尺度**：对全部适用方向检查动作最大范围和alpha边界，分别用实际小尺寸/预览大尺寸/不同DPR检查。已采样帧未见整块角色碰触画布边缘；这不覆盖任意表情叠加或外部参数。

本轮没有发现29个ID中某一项完全没有任何代码路径；但stand在已站立时只有待机、sleep共用sit身体、hop与jump共用轨迹模版、point共用大角度抬臂、angry/scared与多项手势组合退化为相同垂手，必须按上述事实记录。**入口齐全与单元测试通过属于实现证据；完整多视角动作与表情的视觉验收仍未完成。**
