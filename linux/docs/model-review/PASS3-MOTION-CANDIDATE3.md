## 2. 优先修复的确定缺陷

### P1：run 取消把 12 像素跑跳放大到 240 像素，并在 1.2 秒硬落地

候选 2 的 run 竖直速度为零，候选 3 在 `dynamics.py:86–90` 补上正弦轨迹导数。稳定周期 phase=.41 的真实导数约为 -752.934 源像素/秒，这与目前高度、飞行区间 .1 周期及 hz=2.1 相符。但 `motion.py:174–179` 的取消落地统一改用 g=1200，并把到地时间夹在 .08–1.2 秒，破坏原来只有约 .0476 秒的跑步飞行段。

在稳定 run phase=.41 取消的实际结果：

| 取消后时间 | root_y | vy | airborne | 实图含义 |
|---|---:|---:|---|---|
| 0 | -3.708 | -752.934 | True | 原本接近地面的跑步上升段 |
| .2 | -130.295 | -512.934 | True | 取消后反而明显升高 |
| .627445 | -239.920 | ≈0 | True | 上升到原跑步最高位移的约 20 倍 |
| 1.1999 | -43.297 | 686.946 | True | 仍在地面上方 |
| 1.2001 | 0 | 0 | False | 0.2ms 内位置跳 43.3 源像素 |

证据：[run-long-cancel-0.41.png](../../test-results/review-pass-3/motion-fix-3/run-long-cancel-0.41.png)。常规 phase=.3 极值取消表没有命中该短飞行段，这也是必须额外查导数/边界的原因。

下降 phase=.49 同样有问题：起点 root_y=-3.708、vy=752.934，真实到地时间约 .0049 秒；`.08` 下限却令姿态在 root_y 已被 `min(0, trajectory)` 压到地面后仍处 airborne=True、vy 继续增加，直到 .08 秒才进入吸震。`run-cancel-0.49.png` 的 .016/.033/.05 秒就是“已站地面但仍在飞”的区间。

最低修法：让 run 飞行和取消交接共享一个可解释的时间/高度/速度模型。可以保留剩余原飞行曲线到接触点，再交接 land；或重定跑步空中占比、最高点与 g，使用同源的弹道。不要简单清零 vy，也不要只去掉 1.2 秒上限——前者重回候选 2 的速度跳变，后者只修硬落地而保留异常高跳。实际碰撞到地时立刻更改 contact/airborne 并开始吸震，不以最短展示时长代替物理落地时间。进出包络阶段的 vy 还应包含 envelope 的导数。现有源片/腿链可用，不需新图片。

验收：稳定 run 飞行段每 .01 周期取消一次，同时覆盖起势/结束 envelope；接触前后 y、vy 与所选落地模型相符，取消不会产生新的大跳，不得出现 root_y=0 但长期 airborne=True。用 320px 正常尺寸实图看落脚，再用 Pose 数值检验边界。

### P1：转身 MLS 存在交叉 landmark 与整身纹理重影，影响大量动作入口

`render.py:497–514` 对两个完整角色图各做 MLS，再按权重 PLUS 混合。该流程确实不再是候选 2 的整身硬选图，但**并未达到连续转向**：中间帧可见双脸/双发、两套衣裙、脚和尾的残影；left↔back-left 的头顶被挤成高尖锥。`entry-back-nod.png` 的 t=.299/.301、`peak-cancel-1.png` 的 turn 行、`entry-front-look-back.png` 的末格非常清楚。正常尺寸也能看到，不是只在放大图中挑出的边缘噪声。

冻结 `_view_anchors()` 给出以下对应点，坐标已含正常渲染平移（单位源像素）：

| landmark | left x | back-left x |
|---|---:|---:|
| hornLeftTip | 724 | 445 |
| hornRightTip | 486 | 660 |
| hornLeftRoot | 692 | 487 |
| hornRightRoot | 454 | 634 |
| earLeftTip | 721 | 423 |

两组角尖在相邻 45°视图之间交换屏幕左右；线性目标约在 mix=.525 让角尖横坐标重合。角根也交叉。背面眼、鼻、下巴不可见，`keys=a.keys()&b.keys()` 排除了这些点后，交叉的角/耳成为头部的主要约束。需要逐张原图核对解剖身份和可见性，而不能因为字段同名就认定它们是可线性插值的纹理对应。即使身份正确，真正的转向也应经过头表面的深度与遮挡，不能在二维直线穿越。

`kinematics.py:14–40` 的 MLS 没有局部面积、尺度、折叠或形变梯度限制；全画布 24×32 网格还将头/尾的约束作用到其他部位。`_view_anchors()` 以屏幕 x 排序肩/脚，不能保证跨视图仍是同一解剖端点；尾的六个点参与同一整身形变，衣裙又没有轮廓约束。PLUS 可保证已对齐且都不透明的像素不变灰，无法消除两幅不同轮廓/纹理同时出现的问题。

最低修法顺序：

1. 先在原图上逐项核对角、耳、头顶、颈根、肩、髋和足底身份。标出相邻角度的可见/被挡部位，不用“同名”或 x 排序代替解剖对应。
2. 把头/躯干/腿足/尾分层变换，限制 MLS 的作用区域；优先颈、肩、髋、足底的刚性/局部相似配准。加面积符号、尺度范围和 Jacobian 检查，拒绝把轮廓拉成尖锥的中间网格。提高网格密度无法解决错误对应。
3. 缺失的透视应补局部中间头/角/耳/发片或具有深度的局部几何。不可见面由遮挡切换产生，不让两套脸纹理长时间叠加。尾先用自己连续角度/深度和 z 顺序，不让尾尖拉动裙摆。
4. 纹理混合只用于已经重合的材质区；单一外轮廓由几何/遮挡决定。维持转身踏步，但支撑/摆动脚必须与实际 sole 接触一致。

验收：八个相邻方向（含首尾）在 mix=.1/.25/.5/.75/.9 各看全身和头/足近图；每帧只出现一组脸、一组轮廓、两只脚、一根尾，不折叠、不尖头；脚底不被换图带走。再跑本报告六条真实入口，以及转向中途取消/换动作。端点漂亮、队列完成都不能代替这些中间帧。

## 5. 后续复核的最小集合

首先解决 run 的物理时间尺度与交接、转向 cage 对应/遮挡这两项 P1，再修坐裙/回眸的 P2。不要以调整参数个数或增加测试数作为完成指标。

修后最少重跑：run .4–.5 空中段密集取消及起止包络；八组相邻方向的中间角度、六条真实入口与转中断；sit/stand/sleep 混合区正反与中途取消；rear toss 的三种 face 请求；bow blink 取消；jump 与 carried 落地尾边界。若这些变化仍只作用于共用方向/裙/落地模块，再抽看30项起势、极值、末段与代表取消，确认共用修复没有破坏已通过的可靠方向本体。

没有在本报告中把新 native tail、两段腿 IK、头投影、MLS 或 PLUS 的实现存在当作艺术质量保证。已通过项的边界是上表中的动作、方向、时间与交互范围；整体仍未验收。
